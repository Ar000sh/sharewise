# Naming review: feature/settlements

Read-only review of every name the branch adds or changes against `main` (`git diff main...feature/settlements`), judged against `docs/conventions/01` (section 3 vocabulary, 3.5 forbidden words, section 4 method naming), `02` section 2 (test names) and `03`. The working tree was reviewed, including the uncommitted rename to `openDebtPolicy` / `openDebt` / `requireGroupAcceptsSettlementBetween` in `SettlementPaymentService`.

## 1. Overview

- **28 findings: 4 high, 16 medium, 8 low.**
- **Most important:** (1) `SettlementPlanService.openDebt` is the same field problem that was just fixed in `SettlementPaymentService`: a policy named after the value it computes. (2) `OpenDebtPolicy.open(...)` and its local `open`, plus `const open` in `SettleUpTab.PaymentForm`: the bare adjective `open` is still used for the open debt in three places. (3) `SettlementPlan.edge(debtor, creditor)` returns an **amount**, while `edge` / `edges` everywhere else is a **plan entry object**.
- **The pattern behind most findings:** a short word stands in for a domain term (`open` for open debt, `edge` for planned amount, `total` for net balance, `pending` for reserved, `group` for a zero-sum subset). The domain term exists in each case, and sometimes the short word means something else a few lines away.
- Second pattern: the same concept has 3 to 6 names across backend, contract and frontend (section 3). The contract names (`payableAmount`, `pendingAmount`, `SettlementPlanEdge`) are fixed unless you decide on a contract change.
- No forbidden word from 01 section 3.5 appears in **new** production code. The only hits are `cents` in `SettlementPlan` (finding 14) and the old `payer`/`cents` parameters of `MallorcaSliceTest.recordExpense`, which come from `main` (see section 6).

## 4. Rules we could add (for `docs/conventions/03_CODE_STYLE.md`, not edited)

1. **Name a value after its domain noun, never a bare adjective.** Write `openDebt`, not `open`; `plannedAmount`, not `edge`; `netBalance`, not `total`. Single letters only as indexes or in one-line lambdas.
2. **Name a collaborator field after what it is, never after what it produces.** Use the plural of the aggregate it serves for repositories and services (`payments`, `ledgers`), and the type name for anything else (`openDebtPolicy`). A local never repeats the name of a field or method of the same class (`isZero`).
3. **A method name says what it returns or the one rule it checks.** `require…` checks one rule, or its name lists each rule. A helper that takes two values says so (`smallerOf`). Queries start with `find`/`list`/`get` (already 01 section 4; the services added here missed it).
4. **One concept, one word, across Java, TypeScript, tests and docs:** open debt, reserved, net balance, plan edge (the object), awaiting my answer. "group" means the ShareWise group only. When the contract uses another word, the Javadoc of the matching Java name cites it once.
5. **No sentinel `null` meaning "anyone" at a call site.** Wrap it in a named method (`reservedFromDebtor`) so the call says what it sums.

## 5. Not changed on purpose (leave these)

- **Plural collaborator fields** `payments`, `ledgers`, `groups`, `plans`, `notifications`: the established pattern on `main` (`ExpenseService.groups`, `GroupController.groups`). They name the collection the collaborator serves, not a value.
- **`SettlementPayment.waive(groupId, UserId creditor, UserId fromDebtor, ...)`**: `creditor` instead of `toCreditor` is the signature drawn in the diagram (diagram deltas S1).
- **`caller`** in `RecordSettlementPaymentCommand` / `WaiveDebtCommand`: says who acts. The record Javadoc says it is the debtor or the creditor, and the controller fills it from `CurrentUser`.
- **Two classes each named `DebtWaivedListener` and `SettlementPaymentConfirmedListener`** (settlement and notification), with explicit bean names in notification: required by `<Event>Listener` in 01 section 4.
- **`BalancesImpl`**: `Impl` is allowed for an `api` port implementation.
- **Contract names** `payableAmount`, `pendingAmount`, `SettlementPlanEdge`, `listMySettlementPayments`, `getSettlementPlan`, and the controller methods named after these operationIds: contract first. Change them only through `/contract-change`, if at all.
- **`PaymentStatus`, `note`, `createdAt`, `resolvedAt`**: diagram names (S2).
- **`requireGroupAcceptsSettlementBetween`** and **`requireCreditorAndPending`**: the first asks one question in domain words, and its Javadoc lists the four checks in order. The second names both of its checks.
- **The DP locals in `SettlementPlan.zeroSumGroups`** (`mask`, `full`, `sum`, `best`, `choice`, `low`, `n`, `i`): standard bitmask notation, explained by the method Javadoc. Only `cents` and `groups` there are findings.
- **`cents` in the frontend** (`amountToCents`, `eurosToCents`, `payableCents`): 04 section 3 asks for integer-cent helpers. The backend ban in 01 section 3.5 does not apply there.
- **`bobOwesAlice90()`** as `@BeforeEach` in the controller tests: it names the scenario every test in the class starts from.
- **`trip`** (a `GroupId` in `SettlementPaymentServiceDbTest`) and the `alice`/`bob` fixtures: scenario names.
- **`OpenDebtPolicy`** as a class name: it is the one place of the open-debt rule.
- **`Recorded` / `Waived`** result records: the pattern of diagram deltas row 8.
